Methodology

How every probability on this site is produced, in the order the steps run.

1. The match list

HotSpawn's League of Legends pick'em board is read from its own public surfaces: the pick'em lobby page and the fixtures API it calls. That gives the full inventory - match id, tournament, tier, points, lock time and the per-match permalink HotSpawn publishes. HotSpawn's "X% picked" figures are not collected.

2. The external lines

Four independent external sources are read for every refresh:

  • Kalshi - the KXLOLGAME series, a price for a single game of a match.
  • Polymarket - match-winner markets, which price the series and name the best-of format in the title.
  • Pinnacle - the public E Sports guest board: period 0 is the series moneyline, period 1 the map moneyline.
  • Bovada - the esports events feed, moneyline per market period.

A quote is matched to a fixture only when both team names match (normalised, with the filler words "esports", "gaming", "team", "academy" removed) with a score of 0.8 or better, and the pairing has to be consistent in both directions. Every matched quote keeps its own URL.

3. De-vigging

Book prices contain a margin. Two-sided prices are turned back into a probability with p = (1/decimal) / ((1/decimalA) + (1/decimalB)). The size of the margin (the overround) is stored and shown on the row, so the size of the adjustment is auditable.

4. Series versus map

A price for one game is not a price for the series. When only a map price exists, it is labelled external map price only and flagged. It is converted to a series probability only when the best-of format is verified from a source (Polymarket market titles state it), using P(BO3) = p³ + 3p²(1-p) and the equivalent for other lengths. Nothing is converted on a guess.

5. Our own line

Matches no book prices are modelled from verified results taken from Leaguepedia - the tournament match lists and the team "Match History" pages, both read through the wiki's public API. Each result is a series with a date and a winner. Ratings are fitted with a standard Elo scheme:

  • every team starts at 1500;
  • results are processed oldest to newest with K = 32 and no home advantage;
  • a rating is shrunk toward 1500 when a team has few games: r' = (r·n + 1500·8) / (n + 8);
  • the win probability is p(A) = 1 / (1 + 10^(-(rA - rB)/400)).

The rating, the number of rated games and the wiki page behind every team are stored on the row so the number can be re-derived by hand.

6. When there is nothing to fit

If neither an external line nor a verified result history exists for a match, the probability is left at a flat 50%, the row is labelled unverified and it is listed on the Unresolved and Flagged for review pages. No number is invented to fill the gap.

7. Refresh cycle

A scheduled GitHub Actions job runs every four hours (.github/workflows/refresh.yml) and rebuilds the inventory, the lines, the reference data, the picks and this site. Last build: 2026-10-21 21:15 UTC.
