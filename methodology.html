Methodology

Exactly how every probability on this site is produced, and in what order evidence is trusted.

1. The match board

The board is read from Hotspawn's own fixture API, the same data source play.hotspawn.com/lol-pickems renders:

https://phpstack-1372681-6459848.cloudwaysapps.com/api/v1/fixtures

Every record with sport_alias = "lol" and status = "scheduled" is included — that is the full League of Legends Pick'em board, not a filtered subset. Team names, tournament, tier, points, scheduled start time, pick-lock time and Hotspawn's crowd pick percentages all come from this one response.

The lobby HTML is additionally parsed to harvest the server-rendered www.hotspawn.com/matches/… permalinks. Where a fixture is not present in that HTML, its permalink is reconstructed from Hotspawn's public slug pattern and marked unverified on the Flagged for Review page. The fixture record itself is official in both cases.

2. Evidence ladder

TierSourceWhat it gives usConversion
L1 Pinnacle esports moneyline (keyless guest API) Sharp-book price for top-tier LoL American → decimal → implied → de-vigged. Weighted ×2 in consensus.
L1 Unibet Kambi esports feed Independent soft-book price Decimal → implied → de-vigged. Weight ×1.
L1 Polymarket Gamma API Prediction-market price Outcome prices normalised to sum to 1. Weight ×1.
L2 Leaguepedia Cargo ScoreboardGames Official match history for teams with no market Elo + recent-form model with sample-size shrinkage (below).
L3 None available — Nominal 50/50 pick, flagged as unresolved. No edge claimed.

Where several L1 sources price the same fixture, their de-vigged probabilities are averaged with the weights above. Team-name matching is fuzzy (normalised alphanumeric comparison) and is cross-checked against the fixture start time where the source provides one.

3. De-vigging

A two-way book price contains the bookmaker's margin. For decimal prices d1, d2 we compute implied probabilities 1/d1, 1/d2 and normalise them so they sum to 1. That removes the overround and yields the book's implied win probabilities.

4. The originated-line model

  • History window: every completed game in Leaguepedia's ScoreboardGames table in the last 420 days involving any team on the board.
  • Elo: games are replayed in chronological order. Both teams start at 1500, K = 28. The rating difference gives a head-to-head expectation 1 / (1 + 10^((Rb-Ra)/400)).
  • Form: a 90-day win-rate differential is blended 30% into the Elo expectation when both teams have at least 4 games in that window.
  • Shrinkage: the result is pulled toward 50% by a factor n/(n+12), where n is the smaller team's game count. A team with 3 recorded games therefore barely moves off 50%; a team with 40 games is barely shrunk.
  • Confidence labels: Medium when both teams have 10+ games, Low below that, Very thin below 3.

The model is deliberately conservative: when the data is thin it returns something close to even money rather than a confident-looking number it cannot support.

5. What is deliberately excluded

Hotspawn's crowd pick percentages are never an input. The "86% picked" style figures on the Hotspawn lobby are the crowd's own picks for a free Pick'em game. They are a popularity poll, not a line. We record them for reference and label them as such, and no probability on this site is derived from them.

Paid odds-aggregator APIs are not used. OddsPapi, PandaScore, Abios and The Odds API all require an account and key. Since this project must run with no manual input, we only use sources reachable without credentials — listed on the Sources page.

6. Automation & verification

A GitHub Actions workflow (.github/workflows/update-picks.yml) runs the pipeline every 6 hours and on demand. After every run it asserts that:

  • at least one fixture was returned;
  • every pick is one of the two teams on that fixture;
  • prob_team1 + prob_team2 = 1.0 for every row;
  • every method is one of MARKET, MODEL, UNRESOLVED;
  • every row carries a Hotspawn match URL and at least one source link.

Anything that could not be verified is written to data/flagged.json and published on the Flagged for Review page rather than silently filled in.
